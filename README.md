# XHTTP Manager

Self-hosted панель управления XHTTP-маршрутами nginx и входящим доступом к серверу.
Backend: FastAPI, nginx, systemd и nftables. Поддерживаются Ubuntu 22.04/24.04 и Debian 12.

## Возможности

- Одна запись домена с несколькими путями и индивидуальными локальными портами Xray.
- Панель на **http://SERVER_IP/СЛУЧАЙНЫЙ_ПУТЬ**, backend через Unix-сокет. Внешний слушатель 8765 удалён.
- Случайный путь, авторизация, ключ сессий и данные сохраняются при обновлении.
- Firewall: TCP/UDP, IPv4/IPv6, IP/CIDR-белые списки, preview, подтверждение и откат через 120 секунд.
- Светлая/тёмная темы, адаптивная навигация, состояние сервера, поиск и сортировка доменов.
- Root-owned конфигурации и ограниченные helper: веб-процесс не редактирует nginx, sudoers и системные файлы.
- Атомарные ревизии, nginx -t, возврат при ошибке и последние 30 ревизий маршрутов.

## Установка одной командой

Вставьте одну строку в терминал сервера. Она установит curl и сертификаты,
скачает актуальную версию с GitHub и запустит установку.
Вручную загружать или клонировать репозиторий не требуется.

~~~bash
sudo bash -c 'set -Eeuo pipefail; apt-get update -qq; apt-get install -y -qq curl ca-certificates; dir=$(mktemp -d /tmp/xhttp-manager-install.XXXXXX); curl -fsSL "https://raw.githubusercontent.com/ezhikdev/xhttp-manager/main/install.sh?$(date +%s)" -o "$dir/install.sh"; bash "$dir/install.sh" --non-interactive; rm -rf -- "$dir"'
~~~

Эта же команда обновляет старую версию. Предварительно удалять её не нужно.

При необходимости укажите внешний IP сервера:

~~~bash
sudo env PANEL_HOSTS="203.0.113.10" bash -c 'set -Eeuo pipefail; apt-get update -qq; apt-get install -y -qq curl ca-certificates; dir=$(mktemp -d /tmp/xhttp-manager-install.XXXXXX); curl -fsSL "https://raw.githubusercontent.com/ezhikdev/xhttp-manager/main/install.sh?$(date +%s)" -o "$dir/install.sh"; bash "$dir/install.sh" --non-interactive; rm -rf -- "$dir"'
~~~

За NAT укажите внешний IP явно. Несколько IP разделяйте пробелами.
PANEL_HOSTS также допускает отдельное имя панели; его нельзя одновременно использовать как XHTTP origin-домен.

После установки и обновления установщик выводит выделенный блок с адресом панели, действующим
логином и паролем. Логин по умолчанию — admin. Новый пароль также сохраняется в файле, доступном только root:

~~~bash
sudo cat /var/backups/xhttp-manager/<идентификатор>/new-password.txt
~~~

При обновлении пароль не сбрасывается. Если сохранился файл с паролем от предыдущей установки,
установщик проверяет его по действующему хешу и показывает в итоговом блоке. Если старая версия
сохранила только хеш, вместо пароля выводится «сохранён — используйте прежний»: восстановить
исходный пароль из хеша невозможно.

Свой логин/пароль можно передать переменными PANEL_USER / PANEL_PASS.
Не помещайте действующие пароли в публичные скрипты, Git и журналы CI.

### Первое включение Firewall

Установка и обновление **не включают новую ограничительную политику молча**:
это может отключить действующие сервисы. До первого применения раздел показывает «Не включён».

1. Откройте **Firewall** и добавьте разрешения для действующих сервисов.
2. По умолчанию разрешены **TCP 22, 80, 443, 2222**; индивидуальная запись заменяет общее разрешение.
3. Нажмите **Применить правила**, затем **Связь работает — подтвердить** в течение 120 секунд.
4. Только подтверждённая политика сохраняется для загрузки после перезапуска сервера.

После включения остальные входящие TCP/UDP-порты закрыты. Loopback, внутренний Docker-трафик,
ответы на исходящие соединения, ICMP/ICMPv6 и DHCP сохраняются. Дополнительные внутренние
виртуальные интерфейсы, например wg0, можно указать явно.

Для явного запуска первоначальной политики из установщика есть флаг --activate-firewall.
Он требует SSH_CONNECTION, проверяет SSH и также оставляет 120 секунд на подтверждение
в панели. Для нестандартного SSH-порта сначала добавьте разрешение в панели:
установщик не обходит эту защиту.

## Обновление существующей установки

Повторно выполните ту же одну строку на сервере — новая версия скачается с GitHub:

~~~bash
sudo bash -c 'set -Eeuo pipefail; apt-get update -qq; apt-get install -y -qq curl ca-certificates; dir=$(mktemp -d /tmp/xhttp-manager-install.XXXXXX); curl -fsSL "https://raw.githubusercontent.com/ezhikdev/xhttp-manager/main/install.sh?$(date +%s)" -o "$dir/install.sh"; bash "$dir/install.sh" --non-interactive; rm -rf -- "$dir"'
~~~

Сохраняются логин, хеш пароля, ключ сессий, случайный URL, заглушки, origin-записи,
индивидуальные порты Xray и подтверждённая политика Firewall.
**Не задавайте PANEL_PASS**, если не собираетесь менять пароль. Явная смена пароля
также меняет ключ сессий.

При переходе со старой версии:

- Фиксированный /xhttp-manager заменяется случайным путём.
- Плоские записи группируются по домену без потери идентификаторов.
- Старые PBKDF2-хеши с 210000 итерациями остаются действительными.
- Сервис переводится с TCP 8765 на /run/xhttp-manager/panel.sock.
- Чужие сайты nginx и default server не удаляются.
- До изменений сохраняется копия управляемых файлов.
- Новая версия готовится в отдельном release-каталоге.
- Backend проверяется перед активацией nginx.
- При ошибке восстанавливаются код, настройки и предыдущий сервис.

Установщик отказывается от переключения, если порт 80 занят другим веб-сервером
или IP/имя панели уже принадлежит чужому nginx vhost. Чужие службы не останавливаются.
Выберите отдельное имя/адрес или предварительно настройте существующий reverse proxy.
Если nginx не включает conf.d и sites-enabled, подключите
/etc/nginx/conf.d/xhttp-manager.conf явно.

## Домены и несколько путей

В разделе **Домены и пути** создайте, например:

~~~json
{
  "domain": "example.com",
  "paths": [
    {"path": "/api", "port": 10086},
    {"path": "/connect", "port": 10086},
    {"path": "/gateway", "port": 10087},
    {"path": "/xhttp", "port": 10086}
  ],
  "stub_enabled": false
}
~~~

/api обслуживает /api и /api/<session>, но не /api-other.
Вложенные пути используют самый длинный совпавший префикс nginx.
Повторяющиеся пути, включая /api и /api/, отклоняются.

Пути нормализуются и проверяются до генерации nginx. Новые маршруты / и служебные
пути запрещены; старый корневой маршрут сохраняется при миграции.

Заглушка общая для домена. Укажите абсолютный каталог сайта, например /var/www/stub.
Отключённая заглушка возвращает 404. Xray всегда проксируется на 127.0.0.1,
без буферизации и кэширования. Upstream keepalive общий для уникального порта.

## Как работает Firewall

Используется отдельная таблица **inet xhttp_manager**. Команда flush ruleset не применяется.

Для одного протокола/порта существует одна индивидуальная запись:

- **Разрешить**, без IP: разрешение для всех адресов.
- **Разрешить**, с IP/CIDR: доступ только для этих сетей; другое семейство IP тоже закрыто, если отсутствует в списке.
- **Закрыть**: запрет новых соединений, включая порт из списка по умолчанию.
- **Сбросить**: удалить индивидуальное правило и вернуться к политике по умолчанию.

Запись TCP 2222 с адресом 158.1.1.1 разрешает новые соединения только с него;
общее разрешение 2222 её не обходит.

Цепочки входящего трафика и Docker DNAT работают до стандартных filter-цепочек.
Для опубликованных контейнерных портов проверяется исходный внешний порт до DNAT.
Дополнительно фильтруется прямой входящий маршрутизируемый трафик к docker* / br-*.

Существующие соединения сохраняются. SSH-порты обнаруживаются по слушающему sshd, его конфигурации и socket units;
порт 22 защищён дополнительно. Закрытие SSH запрещено. Белый список для SSH
требует активной SSH-сессии и разрешения всех обнаруженных SSH-клиентов.
Текущий IP панели должен иметь доступ к TCP 80.

Изменение сначала проходит nft -c, затем применяется одной транзакцией.
Перед этим root-helper сохраняет прежнюю таблицу и запускает независимый
systemd-таймер. Без подтверждения откат произойдёт даже при остановке панели.
Используется монотонное время: перевод системных часов не продлевает ожидание.
После обновления страницы незавершённое подтверждение можно продолжить.

UFW, firewalld, сторонние nftables/iptables и облачный Firewall продолжают действовать.
Разрешение в панели не отменяет их запреты. Прямое административное редактирование
таблицы xhttp_manager вне панели не поддерживается. Docker bridge с нестандартным
именем нужно явно включить в список внутренних интерфейсов.

### Аварийное восстановление

Через SSH/консоль отмените неподтверждённое изменение:

~~~bash
sudo /usr/local/sbin/xhttp-manager-firewall cancel
~~~

Отключить только Firewall XHTTP Manager, сохранив сторонние таблицы:

~~~bash
sudo /usr/local/sbin/xhttp-manager-firewall disable
~~~

Это root-команда, она не предоставляется веб-сервису через sudoers.

~~~bash
sudo /usr/local/sbin/xhttp-manager-firewall status
sudo /usr/local/sbin/xhttp-manager-firewall restore
~~~

После изменения портов самого SSH сначала скорректируйте разрешения Firewall,
затем перезапускайте SSH. Облачные ACL приложение изменить не может.

## Авторизация и HTTPS

Случайный URL дополняет пароль. Новые хеши PBKDF2-SHA256 используют 600000 итераций.
Действуют ограничение попыток входа, сессии на 8 часов, HttpOnly/SameSite, CSRF,
проверка Origin, CSP, запрет встраивания. Внешние CDN/скрипты не используются.

**HTTP не шифрует пароль и cookie.** Используйте доверенную VPN-сеть или HTTPS.
В базовой установке HTTP остаётся доступным в запрошенном формате.

Для отдельного HTTPS-домена можно создать собственный nginx vhost вне управляемого
файла. Сертификат должен уже существовать:

~~~nginx
server {
    listen 443 ssl;
    server_name admin.example.com;
    ssl_certificate /path/to/fullchain.pem;
    ssl_certificate_key /path/to/privkey.pem;

    location / {
        proxy_pass http://unix:/run/xhttp-manager/panel.sock;
        proxy_set_header Host $http_host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-For "";
        client_max_body_size 128k;
    }
}
~~~

Backend возвращает 404 вне случайного префикса; этот vhost не требует правки
при смене пути. Примените его через nginx -t и reload.
Если вход должен работать **только по HTTPS**, задайте PANEL_HTTPS_ONLY=1 в
/etc/xhttp-manager/config.env и перезапустите сервис. Secure-cookie перестанет
работать через обычный HTTP.

URL меняется в разделе **Настройки**. Старый адрес перестаёт действовать после
успешного применения конфигурации.

## Файлы и сопровождение

| Путь | Назначение |
| --- | --- |
| /opt/xhttp-manager/releases/<версия>/ | Код и отдельное Python-окружение, root-owned |
| /opt/xhttp-manager/app, /opt/xhttp-manager/venv | Ссылки на действующий релиз |
| /etc/xhttp-manager/config.env | Логин, хеш, ключ сессий, параметры сервиса |
| /etc/xhttp-manager/data/settings.json | Сохраняемый URL и настройки |
| /etc/xhttp-manager/data/origins.json | Совместимое зеркало старого формата origin |
| /etc/xhttp-manager/nginx-revisions/current | Атомарная ревизия, источник маршрутов и URL |
| /run/xhttp-manager/panel.sock | Unix-сокет backend |
| /var/lib/xhttp-manager-firewall/ | Root-only подтверждённая/ожидающая политика |
| /var/backups/xhttp-manager/<идентификатор>/ | Резервная копия установки/обновления |

Веб-пользователь может записывать advisory lock и runtime-каталог сокета.
Данные, настройки, nginx и релизы принадлежат root. Sudoers разрешает только
фиксированные helper и ограниченный набор операций.

~~~bash
sudo systemctl status xhttp-manager
sudo systemctl restart xhttp-manager
sudo journalctl -u xhttp-manager -f
sudo systemctl status xhttp-manager-firewall
~~~

Старые release-каталоги и резервные копии сохраняются для ручного восстановления.
Контролируйте место и удаляйте ненужные копии после проверки обновления.

## Тестирование и ограничения

См. [TESTING.md](TESTING.md) и [CHANGELOG.md](CHANGELOG.md).
Сеть рабочей станции и общего тестового хоста не изменяется.
Реальные nftables/nginx проверяются в отдельных user/network namespaces;
установщик дополнительно получает отдельные mount namespaces.

Загрузка systemd после настоящего reboot, пакетная установка apt и работа с Docker
daemon в предоставленном окружении не проверены: тестовый пользователь не имеет sudo.
Проверены реальные сетевые пакеты, Docker-подобный DNAT, nginx и миграция установки
с тестовой заменой планировщика/служб в изолированной среде.
